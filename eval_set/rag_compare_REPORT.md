# CourseRAG 集成对比评测（2026-08-22）

## 一句话结论

**web+rag 与纯 web 命中率持平（0.83），但耗时 -18%（443s vs 541s）、token -4%，且 course_retrieve 真实参与 60 次、报告引用课程库来源——集成不劣于纯 web 且更高效；命中率未提升的原因是评测题选得不好（见下方分析）。**

## 数据

| 模式 | 平均命中 | 平均耗时(s) | 总 tokens | course_retrieve 调用 |
|---|---|---|---|---|
| 纯 web | 0.83 | 541.0 | 2,054,876 | 0 |
| web+rag | 0.83 | 443.0 (-18%) | 1,965,934 (-4%) | 60 |

| 任务 | web 命中 | web+rag 命中 | web+rag 的 course_retrieve 调用 |
|---|---|---|---|
| #1 ACID 特性 | 1.0 | 1.0 | 11 |
| #2 死锁四条件 | 0.5 | 0.5 | 8 |
| #3 2NF/3NF | 1.0 | 1.0 | 11 |

## 诚实分析（必须讲）

1. **为什么命中率没提升**：三道题都是"通用课程知识"（ACID/死锁/范式），**web 搜索本身就能答好**——RAG 的私有知识优势没有机会体现。要证明"RAG 提升准确率"，评测题必须选 **web 搜不到或搜不准、只有课程库有**的私有知识（如老师课件里的特定表述、教材独有的例题）。
2. **为什么仍然有价值**：
   - **效率提升**：web+rag 平均每条快 98 秒（-18%）、省 4% token——course_retrieve 一次调用替代多轮 web 搜索，链路更短；
   - **工具真实生效**：60 次调用，任务 #3 的报告明确引用了"课程知识库：data\数据库-函数依赖与范式.md"（3NF 定义、传递函数依赖、范式对比小结）；
   - **零副作用**：RAG 服务不可达时自动降级 web（评测期间 RAG 在 8000 端口，全部正常）。
3. **局限**：样本仅 3 题 × 2 模式，单次运行，命中率有随机波动（#2 两种模式都漏"不可剥夺/请求并保持"两个词，非 RAG 能救的范畴）；严谨结论需更大样本 + 私有知识题。

## 改进方向（下轮评测）

- 评测题改为"教材独有知识点"（web 搜不到）：如微信小程序教材里的特定 API 用法、Streamlit 手册里的冷门配置、Linux 课件的特定命令；
- 加"课程库命中情况"指标：报告里是否出现 data\ 来源引用（可脚本匹配）；
- 样本扩到 6-10 题。
